# Home Network Monitor

Day 19 of [Ship 100](https://august85.github.io/ship100/). Raspberry Pi project.

A list of devices on your Wi-Fi, with alerts for new ones.

**Plan**
1. Main flow: every 5 min, ping-sweep the /24, read the ARP table, diff against known devices, alert on new MACs.
2. Data source: the kernel ARP table (`ip neigh` / `arp -an`) plus a bundled MAC-prefix → vendor list. No cloud.
3. Output: `devices.html` + `devices.json` dashboard, optional `--serve PORT`, optional push via ntfy.sh / webhook.
4. Device naming and a `--list` view from the command line.
5. Out of scope: nmap-style port scans, blocking devices, router APIs, IPv6-only devices, a web UI for naming.

Live page: https://august85.github.io/ship100/days/019-home-network-monitor/ · sample dashboard: [demo.html](demo.html) (generated by `--mock`).

## Run it

```bash
cd app
python3 main.py --mock --once        # pretend network; run 3× to see a "new device" alert
python3 -m unittest test_main        # 6 tests
python3 main.py --serve 8088         # real network, scan every 5 min, dashboard on :8088
python3 main.py --list
python3 main.py --name aa:bb:cc:dd:ee:ff "Kitchen speaker"
```

Options: `--subnet 192.168.1.0/24`, `--interval 300`, `--no-sweep`, `--data <folder>` (default
`~/.local/share/home-network-monitor`, or `HNM_DATA`), `--alert-url https://ntfy.sh/<topic>` (or `HNM_ALERT_URL`).
Extra vendor names go in `<data>/vendors.json` as `{"aa:bb:cc": "Name"}`.

Run at boot: copy `app/` to `/home/pi/home-network-monitor/`, copy `service.service` to
`/etc/systemd/system/home-network-monitor.service`, then `sudo systemctl enable --now home-network-monitor`.

## How it works

- The first scan is the baseline and never alerts. After that, any MAC not in `known.json` alerts once.
- A ping sweep fills the ARP table so quiet devices show up; no root needed (uses the system `ping`).
- Phones with Wi-Fi privacy on use a "locally administered" MAC; these are labelled *Private address* so a
  phone re-randomising its address is recognisable as such rather than a mystery gadget.
- The built-in server only serves `devices.html` and `devices.json`, nothing else in the data folder.

## Decisions made on the day (unattended run)

- Standard library only, so it runs on any Pi OS without `pip install`. A short vendor table (~90 prefixes)
  is bundled instead of the full 5 MB IEEE OUI file.
- Alerts use ntfy.sh because it's free, keyless and has phone apps; any URL that accepts a POST works.
- Smoke-tested on a Mac against a real LAN (`--no-sweep`, found 7 devices). Not yet run on actual Pi hardware.
- Screenshots were taken with headless Chrome from the mock dashboard; no real network data is in the repo.
